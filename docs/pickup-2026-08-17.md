## What changed, in one paragraph each

**Motion became a real Style Guide axis.** The rhythm controls used to be React
state on the gallery's own element — saved nothing, reached no page, reset on
reload. They now write the same draft colour and type write, and promote through
the same button into the marker block in `globals.css`. Almost nothing new was
built: the export already ships that file wholesale and `setPageExportApproval`
already fingerprints the block, so reload survival, pagebuilder, staged pages and
export all came free. The handoff's suggested "Copy as CSS" affordance was
rejected — a write path from a dev screen into the stylesheet is what the Style
Guide already was.

**Token groups are data.** `src/content/motion-tokens.ts` declares them; the
draft defaults, the live preview, the promoted CSS, the validators and the
control panels all derive from it. Every suite declares `controlGroups`, required,
so a suite that skips the question does not compile.

**The spine was split from Rise.** `--anim-reveal-duration/-delay-step/-easing`
were read by every suite while being named for one; they are `--anim-duration`,
`--anim-stagger`, `--anim-easing` now, and each suite owns a duration, stagger
and easing that inherit from them. Rise got a module of its own, because the
distance was always Rise's and only ever looked shared.

**Three suites were added.** Fade (`fade`), Settle (`settle`), and four
load-triggered variants for heroes (`reveal-load`, `fade-load`, `wipe-load`,
`settle-load`). `scrub` was retired outright.

**Colour:** the service arrows stopped vanishing on chromatic recipes, and the
hover pair became card-keyed rather than ground-keyed.

Full detail is in `docs/animation-axis-handoff.md`, which was updated four times
this session and is current. `docs/builder-workflow.md` §1 and §2 and `AGENTS.md`
were updated too.

## The traps, and both cost real time

**1. `npm run css:verify` reported OK while the served CSS was two edits behind.**
Twice. The dev server silently stops recompiling `globals.css`, `touch` does not
always shake it loose, and the guard that exists precisely to catch this said
everything was fine. Restarting with `npm run dev:fresh` fixed it both times.

If a CSS symptom does not match the source, **fetch the stylesheet and grep it**
rather than trusting the script:

```js
const href = [...document.querySelectorAll('link[rel=stylesheet]')][0].href;
const txt = await fetch(href, {cache:'reload'}).then(r => r.text());
```

And grep for the **minified** form. A check for `inset(-0.35em` reported a
false failure because the emitted CSS says `-.35em`.

**2. `/sections` renders nothing until you expand an individual section.** It is
a two-level accordion — `<details>` per mode group, and inside each a per-section
accordion whose preview is `{isOpen ? … : null}`. Opening the mode groups lists
the sections; it does not mount them. A DOM query on a freshly loaded page finds
no images and no marker classes, which looks exactly like a section having failed
to register. I concluded that twice, wrongly. It is written into
`builder-workflow.md` §2 now.

**3. A backgrounded tab freezes CSS animations.** Values read identical at every
sample and it looks like the animation is not running. Read
`element.getAnimations()[0]` and set `currentTime` to measure the real curve —
that is how both the Settle snap and the Focus easing problem were actually
found.

## Open, in the order I would pick them up

**Nothing has been watched through a real page load.** Every load-suite check
drove the attribute on an already-painted page. A hard reload with `reveal-load`
set on the hero is the one thing that would confirm the no-flash claim end to
end. This is the only unverified claim in the animation work.

**`--anim-pulse-delay` is promoted at 480ms** against a 180ms shipped default.
It makes the beat land a beat-and-a-half after the section settles. Possibly
deliberate, possibly left over from a session of dragging sliders — the other
seven values in that shape were reset, this one was not.

**`accent` is still marked on no section.** Two suites describe behaviour for it
(Wipe scales it, Focus blurs it), so half of each is visible only in the gallery.
The role is kept deliberately; it needs a pass to find stat figures and badges.

**One hero has a load entrance; nine do not.** `HeroSplitFullHeightSectionV3` is
in `loadEntranceComponents`. `HeroFullscreenSectionV2` **cannot** join it as
things stand: it renders no `<img>` at all, its photograph comes from the
ground-image axis as a `background-image` on the frame's `::before`. Settling
that means animating a pseudo-element the frame owns, which also has to negotiate
with `background-attachment: fixed` on the parallax treatment. That is a new
mechanism, not a marking job.

**If a third suite ever travels**, `--anim-reveal-distance` and
`--anim-settle-distance` should collapse into a spine token the way duration and
stagger did. Two is not yet a shared travel.

## Two rules worth not relearning

**`settled` has no CSS rule and must not gain one.** Animating that state is the
obvious way to give an above-the-fold section an entrance, and it reintroduces a
flash: the observer runs on mount, *after* first paint, so anything hung off it
blanks content the reader is already looking at. Load suites use no animation
state at all — their gate is the server-rendered attribute, so they run from
first paint with no JavaScript in the path.

**Per-suite tokens are safer than per-suite controls on a shared token.**
`motion-token-agreement` fails any control whose token no rule reads, so an
unread `--anim-pulse-stagger` gets caught. A Pulse control pointed at the *shared*
stagger would not, because that token is read elsewhere. The shape that looks
riskier is the one the tests can see.
