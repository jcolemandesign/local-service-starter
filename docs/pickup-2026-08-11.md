## 2. The accent-role bug class

Eyebrows and card links are the same token (`text-service-accent` →
`--live-service-accent` → `--recipe-eyebrow`), which turned out to be **the one
role in the system that was not ground-relative**. Three places:

- **A card is a ground, and the accent never re-resolved on one.** Every ladder
  role re-declares from `--recipe-card-text`; the chromatic role inherited the
  section's already-substituted colour. Harmless on the recipes' own cards, 1.36:1
  the moment a `cardSwatch` override flips polarity. Fixed by `deriveTintMode`
  (lightness + OKLab chroma) shipped as `data-pagebuilder-card-chroma`.
- **The gate had the same blind spot** — `eyebrow` was measured on `"ground"`
  only while every ladder role was measured on both surfaces. Now measured on
  the card too.
- **`--live-bg-muted` was frozen, but only after a style guide is promoted.**
  `@theme inline` substitutes a fallback at the element using it, so the token
  followed the recipe on a cold start and stopped once the generated `:root`
  block pinned it. Added to the role table, derived from `--recipe-card`.

`section-colour-ownership.test.ts`'s fixed-fill guard was widened to the accent
tokens; it caught three carousel/marker chips painting accent on `bg-white`,
now on `bg-service-surface`.

### Watch out for
`--recipe-eyebrow: var(--card-eyebrow, var(--recipe-eyebrow))` is a **cycle** —
a var() in a *fallback* still counts. It makes the property invalid at
computed-value time and the whole chain falls through to the `@theme inline`
default (`#1f7a5a`), which shows up as an out-of-palette green on card icons.
Fixed by repointing `--live-service-accent` / `--live-text-accent` instead, one
link further along. There is now a standing check in
`color-css-agreement.test.ts` that no custom property references itself.

## 3. Contrast card (carousel alternation)

The services carousel alternates surface cards with a dark "view all" card. That
card was a literal `bg-bg-dark` — a fixed token — so the alternation read on the
two light recipes and vanished on the other six.

Each recipe now declares `--recipe-contrast-card` / `--recipe-contrast-card-text`
opposite its own ground, surfaced as `bg-contrast-card` /
`text-contrast-card-ink`. Fallbacks are the old literal pair, so off-recipe
rendering is unchanged. `contrast-card-alternation.test.ts` checks all eight
recipes on two palettes (48 assertions).

**The rung is available to any section that wants an emphasised or alternating
card** — this is the first consumer.

## 4. Shell branches drop toggles

`PagebuilderShell` has ~42 hand-written render branches that **never go through
`withSectionToggles`**; every prop is passed by hand, so each branch is a chance
to drop an axis. This is what made the services hero's alignment and card-links
look broken — the control moved, the value saved, the canvas ignored both.

Fixed there and in `ContentThreeColumnMixedSectionV3` (`cardLinks`, dropped at
some earlier point). `pagebuilder-shell-branch-toggles.test.ts` now checks every
branch against the membership sets.

## 5. Nav in the builder canvas

The nav used to detect the builder and return early — no scroll listener,
statically in flow. The reason was real: the canvas is its own `overflow: auto`
scroll container, so `window.scrollY` never moves there.

Now scroll-container-aware (`getScrollContainer` walks to the nearest actually
scrolling ancestor, falls back to `window`), and the hero-passed measurement
subtracts the container's offset so both sides share a coordinate space. The
canvas already carries `container-type: size`, whose layout containment makes it
the containing block for `position: fixed`, so the nav pins to the canvas rather
than escaping over the builder chrome. `isPagebuilderPreview` is gone — one code
path for site, previews and builder.

> **Open trade-off, not yet decided.** The revealed nav is `z-30` and fixed, so
> it overlays the top ~80px of whatever section is under it and a click there
> selects the nav instead of that section. That matches the live site, but it is
> a change to how the canvas selects. Making the revealed nav click-through in
> the builder only is a small change if it turns out to be annoying.
